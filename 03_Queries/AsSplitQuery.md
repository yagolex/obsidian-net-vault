**Кратко:** `AsSplitQuery()` заставляет EF Core выполнять include’ы несколькими запросами вместо одного огромного JOIN.

`var orders = context.Orders     .Include(o => o.Items)     .AsSplitQuery()     .ToList();`

### Что это

- По умолчанию EF Core (5+) делает **single query** для графа (`Include`/`ThenInclude`).
    
- `AsSplitQuery()` переключает стратегию на **много запросов**:
    
    - 1 запрос – за основными сущностями.
        
    - Отдельные запросы – за навигационными коллекциями/сущностями.
        
- Обратный метод – `AsSingleQuery()`.
    

### Когда использовать

- Когда **один большой запрос** рождает:
    
    - чудовищный `JOIN` с кучей дубликатов строк;
        
    - взрыв трафика и памяти;
        
    - падение производительности БД.
        
- Когда:
    
    - много `Include`-ов с коллекциями;
        
    - сложные фильтры + сортировки.
        

### Подводные камни

- Больше round-trips к БД → может быть хуже при **очень маленьких** наборах данных.
    
- Поведение с `Skip/Take`, `GroupBy`, `Distinct` и сложными проекциями – лучше заранее проверять.
    
- Может иначе влиять на блокировки/план выполнения.
