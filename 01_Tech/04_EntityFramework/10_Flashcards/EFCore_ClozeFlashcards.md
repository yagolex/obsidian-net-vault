# EF Core Cloze Flashcards
#flashcard

EF Core supports ==Eager Loading== and ==Lazy Loading== for fetching related data.

In EF Core, ==Optimistic Concurrency== assumes no conflicts until save time, while ==Pessimistic Concurrency== locks data to prevent conflicts.

To disable Change Tracking for read-only queries, use the method ==AsNoTracking()==.

To load related data along with the main entity in a single query, use ==Include()==, and to load data from a related entity, use ==ThenInclude()==.

EF Core migrations are created with the CLI command ==dotnet ef migrations add== and applied with ==dotnet ef database update==.

A ==Navigation Property== in EF Core represents a reference to another entity, while a ==Shadow Property== exists in the model but not in the entity class.

The component that tracks entity state changes in EF Core is called the ==Change Tracker==.

Entity states in EF Core include ==Added==, ==Modified==, ==Deleted==, ==Unchanged==, and ==Detached==.

In EF Core, ==Eager Loading== loads related data immediately, whereas ==Lazy Loading== loads it upon first access.

To load related data explicitly in EF Core, use ==context.Entry(entity).Collection(...).Load()==.

Using ==AsNoTracking()== improves performance for read-only queries by disabling the Change Tracker.

A ==Compiled Query== in EF Core avoids the cost of translating a LINQ query multiple times.

To execute raw SQL safely in EF Core, use ==FromSqlInterpolated()== or parameterized queries.

Transactions in EF Core can be handled using ==DbContext.Database.BeginTransaction()== or ==TransactionScope==.

==Optimistic Concurrency== detects conflicts at save time, while ==Pessimistic Concurrency== uses locks to prevent conflicts.

To enable Lazy Loading, install ==Microsoft.EntityFrameworkCore.Proxies== and enable it in the context configuration.

The ==N+1 problem== occurs when multiple queries are issued for related data, often in a loop.

To solve the N+1 problem, use ==Eager Loading== or projection.

==Value Conversions== allow EF Core to convert property values when reading from or writing to the database.

A ==Shadow Property== is not in the entity class but is tracked by EF Core.

Relationships in EF Core can be configured using the ==Fluent API== or ==Data Annotations==.

==HasKey()== defines the primary key, while ==HasAlternateKey()== defines an alternate unique key.

A ==Navigation Property== points to related entities.

A ==Foreign Key== links one entity to another.

SQL generated by EF Core can be logged using ==ILoggerFactory== or the ==LogTo== method.

==Database First== generates models from an existing database; ==Code First== generates the database from models.

Initial data can be seeded in EF Core using ==HasData()== in the model builder.

==Owned Entities== do not have their own identity and are part of another entity.

Multiple DbContexts can be used by configuring each with its own ==DbContextOptions==.

EF Core can run without a database using the ==InMemory== provider.

A ==Split Query== loads related collections with separate SQL queries.

A ==Single Query== loads related collections in one SQL query.

Performance issues in EF Core can be detected using ==logging==, ==profiling tools==, and checking for excessive queries.

Stored procedures can be executed using ==FromSqlRaw()== or ==ExecuteSqlRaw()==.

==ToListAsync()== executes a query asynchronously and materializes the results into a list.

To disable Change Tracker for a query, use ==AsNoTracking()==.

A ==Compiled Model== pre-builds model metadata to improve startup performance.

A transaction can be rolled back using ==transaction.Rollback()==.

==First()== throws if no element matches; ==FirstOrDefault()== returns the default value.

Pagination in EF Core is done using ==Skip()== and ==Take()==.

LINQ queries in EF Core can be executed asynchronously using ==ToListAsync()== or similar methods.

Default values for a property can be set using ==HasDefaultValue()==.

==Add()== marks an entity as Added (to be inserted); ==Attach()== marks it as Unchanged (only tracked).
