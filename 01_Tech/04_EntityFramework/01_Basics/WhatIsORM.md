# WhatIsORM


## 📜 Interview-Ready Explanation
**ORM (Object-Relational Mapping)** — это подход и набор инструментов, позволяющий работать с базой данных **через объекты и классы языка программирования**, а не напрямую через SQL-запросы.

## Идея своими словами

Вместо того чтобы писать:
```csharp
`SELECT * FROM Customers WHERE Id = 1;`
```
и вручную превращать строки результата в объекты C#,  
ORM позволяет просто написать:
```csharp
`var customer = db.Customers.First(c => c.Id == 1);`
```
и ты сразу получаешь готовый объект `Customer`, с которым работаешь как с обычным C#-объектом.

## Как это работает внутри

1. **Классы → Таблицы**  
    ORM сопоставляет твои C#-классы (свойства, связи) с таблицами и колонками в базе.
    
2. **Запросы LINQ → SQL**  
    Когда ты пишешь LINQ-запрос, ORM транслирует его в SQL, оптимизирует и отправляет в БД.
    
3. **Результат → Объекты**  
    ORM берёт строки из БД и материализует их в объекты соответствующего типа.
    
4. **Изменения → UPDATE/INSERT/DELETE**  
    ORM отслеживает, что изменилось в объектах (через Change Tracker), и при `SaveChanges()` сам формирует нужные SQL-команды.

## Примеры ORM

- **Entity Framework Core** (C#, .NET)    
- Hibernate (Java)    
- Django ORM (Python)    
- SQLAlchemy (Python)    
- Sequelize (JavaScript/Node.js)   

---

## Преимущества ORM

- 📉 **Меньше кода SQL** — меньше рутины и ошибок при маппинге данных.    
- 🛠 **Единый объектный стиль работы** — одинаковый синтаксис для разных СУБД.    
- 🔒 **Защита от SQL-инъекций** — параметры передаются безопасно.    
- 🔄 **Отслеживание изменений** — Change Tracker упрощает сохранение.    
- ⏳ **Кросс-БД переносимость** — можно сменить движок (SQL Server → PostgreSQL) с минимальными правками.    

---

## Недостатки ORM

- ⚡ Потери производительности на сложных запросах.    
- 🕵 Меньший контроль над оптимизацией SQL.    
- 📚 Нужно понимать, как ORM генерирует SQL, чтобы избегать ловушек (N+1, лишние JOIN'ы, неиспользование индексов и т.п.).
