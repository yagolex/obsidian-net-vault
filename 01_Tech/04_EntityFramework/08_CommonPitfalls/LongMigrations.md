# Long Migrations in EF Core
tags:: #efcore #migrations #pitfalls

## 💡 Concept
Долгие миграции — одна из распространённых проблем в проектах с длительным циклом разработки.  
Чем дольше живёт проект, тем больше миграций и риск конфликтов, дублирования и ошибок при применении.

---

## ⚠️ Проблемы
- Сотни мелких миграций замедляют билд и деплой.
- Конфликты при объединении веток с разными миграциями.
- Ошибки при откате и повторном применении (особенно при изменении уже применённых миграций).
- Накопление неиспользуемых таблиц, индексов, старых колонок.

---

## ✅ Лучшие практики
1. **Слияние старых миграций** (squash):
   ```bash
   dotnet ef migrations remove
   dotnet ef migrations add InitialCreate --force
   ```
2. **Хранить schema snapshot под контролем версий** (`ModelSnapshot`).
3. **Очищать старые миграции** при релизах (раз в несколько месяцев).
4. **Тестировать миграции на CI/CD**:
   ```bash
   dotnet ef database update --connection "..."
   ```
5. **Разделяйте ответственность**: schema‑миграции и seed‑данные отдельно.
6. Не правьте миграции вручную без понимания — лучше создать новую.

---

## 🧠 Рекомендации
- Для больших проектов — иметь «базовую миграцию» (например, `V1_Initial.sql`) и хранить последующие отдельно.
- Для CI — применять миграции в чистую тестовую БД перед деплоем.
