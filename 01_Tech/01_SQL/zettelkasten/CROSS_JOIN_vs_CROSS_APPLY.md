# CROSS JOIN vs CROSS APPLY in SQL

## 🧩 1. CROSS JOIN

`CROSS JOIN` создаёт **декартово произведение** двух таблиц: каждая
строка из левой таблицы соединяется с каждой строкой из правой.\
→ Он **не зависит** от значений в таблицах.

### 🔹 Пример

``` sql
SELECT e.Name, d.DepartmentName
FROM Employees e
CROSS JOIN Departments d;
```

Если у тебя 10 сотрудников и 3 департамента, результат будет **10 × 3 =
30 строк.**

> ❗ `CROSS JOIN` не имеет `ON`-условия и не может ссылаться на колонки
> из левой таблицы для фильтрации данных правой --- он просто
> комбинирует всё со всем.

------------------------------------------------------------------------

## 🧩 2. CROSS APPLY

`CROSS APPLY` --- оператор для связи таблицы с табличной функцией (или
подзапросом), который **может использовать значения из левой таблицы**.

Он работает **как "для каждой строки слева --- выполни выражение
справа"**.\
Похож на **LATERAL JOIN** в PostgreSQL.

### 🔹 Пример с табличной функцией

``` sql
SELECT c.CustomerName, o.*
FROM Customers c
CROSS APPLY dbo.GetRecentOrders(c.CustomerId) AS o;
```

👉 Здесь `GetRecentOrders()` вызывается **отдельно для каждого
клиента**, и возвращает только его заказы.

------------------------------------------------------------------------

## 🧩 3. OUTER APPLY

`OUTER APPLY` аналогична `LEFT JOIN`: если правая часть ничего не
вернёт, строка из левой всё равно сохранится (с `NULL`-ами).

``` sql
SELECT c.CustomerName, o.OrderId
FROM Customers c
OUTER APPLY dbo.GetRecentOrders(c.CustomerId) AS o;
```

------------------------------------------------------------------------

## 🧩 4. CROSS APPLY без функций

`CROSS APPLY` можно использовать с подзапросом:

``` sql
SELECT e.Name, d.TopProject
FROM Employees e
CROSS APPLY (
    SELECT TOP 1 p.ProjectName AS TopProject
    FROM Projects p
    WHERE p.EmployeeId = e.Id
    ORDER BY p.Priority DESC
) d;
```

→ Для каждого сотрудника выбирается **только один** проект (по
приоритету).\
`CROSS JOIN` не позволил бы этого сделать.

------------------------------------------------------------------------

## ⚙️ 6. Пример производительности

``` sql
-- CROSS JOIN
SELECT COUNT(*) 
FROM Orders o
CROSS JOIN OrderDetails d;

-- CROSS APPLY (на каждый заказ берём только 1 строку)
SELECT o.OrderID, d.ProductID
FROM Orders o
CROSS APPLY (
    SELECT TOP 1 ProductID 
    FROM OrderDetails d2 
    WHERE d2.OrderID = o.OrderID 
    ORDER BY d2.Quantity DESC
) d;
```

План выполнения покажет: - `CROSS JOIN` создаёт полное декартово
произведение (затратно по памяти и CPU); - `CROSS APPLY` вызывает
подзапрос построчно --- эффективно при фильтрации по ключу.

------------------------------------------------------------------------

## 💡 Вывод

-   **`CROSS JOIN`** --- простое перемножение строк, используется
    редко.\
-   **`CROSS APPLY`** --- мощный инструмент для **коррелированных
    подзапросов** или **табличных функций**, аналог `LATERAL JOIN`.\
-   **`OUTER APPLY`** --- аналог `LEFT JOIN` для таких случаев.
